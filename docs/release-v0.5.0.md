## Build recipe and provenance

The v0.4.0 tag's `cmd/abapiti/main.go` used build-time `-X main.version`; it
contained no 0.4.0 default version literal. The remaining 0.4.0 references in
the repository are historical release links, not active version settings.
v0.5.0 sets the default to 0.5.0 and still supports the build-time override.

There was no checked-in v0.4.0 release script/Makefile. The old README describes
six-platform binaries and bundles containing abapiti, the OSG native client and
the check kit. The documented CLI emits the Go module/native report and
`osabap.mjs` documents GOOS/GOARCH cross-builds. `tools/release-build.sh`
codifies that recipe and mirrors the old asset names, adding the test zip and
trace/diff-deployment JSON companions. The corpus repository is unchanged
since v0.4.0. The supplied kit zip is copied byte-for-byte, not regenerated.

```sh
# Existing clean pinned checkouts; do not clone or connect to SAP.
export GOTOOLCHAIN=go1.26.0 GOFLAGS=-buildvcs=false
export GOCACHE="$GO_BUILD_CACHE" TMPDIR="$SCRATCH"
export TRANSPILER="$PINNED_TRANSPILER" npm_config_cache="$NPM_CACHE"
export ABAPITI_OSG_HOME="$OSG_HOME"
# Admit at load <12; do not nest the same lock inside this scope.
flock "$OSG_HEAVY_LOCK" systemd-run --user --scope -p MemoryMax=48G nice -n 10 \
  bash tools/release-build.sh "$ABAPLINT_HOME" "$OSG_HOME" "$KIT_ZIP" \
  "$ASSETS" "$BUILD"
```

All large outputs belong on caller-owned RAM scratch. The script limits the
Node heap to 24 GiB; the actual two-package lint otherwise exceeds Node's
default heap. `RELEASE_RESUME=packages` resumes at package lint/packaging only
when the same source revision and pins already emitted both complete packages
in the same BUILD. Do not use it to combine stale or partial source tables.
Native OSG report compilation uses `-p 1`, `-N -l -dwarf=false`, stripped
symbols and no gogen line directives, the existing bounded compile mode.

The ordinary full default CLI and the release's A4H pair are distinct emissions:
`abapiti abaplint` translates only core plus deployment harness;
`abaplint-tests --target a4h` translates the 17-shard union once, then partitions
core/tests with a shared name/shape table. The release OSG client uses exactly
that pair's core and has no test-package dependency. Both standalone full-core
emissions are checked against Node, not assumed equivalent from their names.

The required local zabapgit helper was invoked against the default build and
OSG pin. Its hard-coded OSG `.out` directory could not be created (`ENOENT`),
so its successfully generated full default source was passed to the existing
`a4h-zabapgit-check.mjs` external-root builder with the same kit and bounded
compiler flags. Neither helper nor OSG sources were edited.

## Scope

`--scope core` is the default: all rules, readable names, binary64 numbers,
no reachability pruning. `--scope zabapgit` retains the legacy hashed/pruned
assume-integer build. `--full` still measures raw lowering/HIR gaps and emits
no targets. The emitted full client retains source-located unsupported-body
refusals, rather than making unsupported operations silently succeed.

A4H zips are build-only. Activate `$ZLNT` before `$ZLNT_TESTS`; do not mix with
the old hashed `$ZABAPLINT`. PCRE requires 7.55; SAP jobs, ST22, PXA and actual
kernel regex behavior remain coordinator-side gates. See
[a4h-test-suite.md](a4h-test-suite.md) for the durable runner/collection contract.

- Full 17-shard package build: 2,167 files, zero blocking diagnostics, zero HIR
  errors, zero coverage traps. Core: 2,338 objects; tests: 5,002 (excluding DEVC).
  Actual package-source lint: 7,340 files, zero issues (the existing PCRE v755
  exception). No SAP activation was attempted.
- Both the ordinary full default and the release's shared-core client match
  the zabapgit Node kit byte-for-byte: clean **0**, seeded **5**, on Go and OSGO.
  Fresh original pinned Node was rebuilt independently and checked against
  both kit expectations and the emitted Go client.
- `keyword_case` **2**, `line_only_punc` **1**, `sequential_blank` **1** issue:
  exact Node issue dumps (key, severity, filename, ranges, message), through
  both ordinary full-default binaries and the final release Go/OSG binaries.
  Every client exits 0; no `zlnt_exception_un_` or other refusal/trap. The sample
  and per-rule configs are generated by `tools/release-rules-check.mjs`.
- Mandatory `hir-unit.sh` with `HIR_RUNTIMES=" "`: exit 0. `go vet ./...`:
  exit 0. Regular short Go suite: exit 0 with optional OSG execution unset;
  every one of the 17 `tools/*-test.mjs` scripts runs separately, exit 0.
  Lint versus `origin/main`: **0 new**, canary 5/5, golangci-lint 2.13.2.
- **The exact short command with `ABAPITI_OSG_HOME` enabled exits 1**:
  `TestParsedNestedObjectABAPHost` (nil data dereference) and
  `TestLSPErasedInNodeOracle` (expected abap_true) fail. Both failures were
  independently reproduced from an `origin/main` source archive on the same
  OSG pin. This is a baseline optional-host gate gap, not a green run or a
  waived new regression; no test was removed or marked passing. It was already
  documented by the packaging branch in `a4h-test-suite.md`.

All six platform variants are cross-compiled; standalone issue comparisons are
executed on linux-amd64 only. No asset is omitted. The default Node heap failure
was resolved by the explicit heap cap, then package lint completed successfully.
